# W0-04 — admin-only OpenRouteService proxy

Date: 13 September 2026  
Status: **Implementation, automated verification, server-secret setup (new key, distinct from the exposed one) and live-provider verification passed. Revocation of the old exposed key is still pending: ORS still accepted it at the last check, so W0-04 is not complete.** See "Rotation status" below.

## Implemented boundary

- Browser requests now use the existing Firebase-authenticated API helper:
  - `POST /api/geo/geocode` — `{query}` → `{point: {lat, lng} | null}`.
  - `POST /api/geo/directions` — `{start: {lat, lng}, end: {lat, lng}}` → `{path: [{lat, lng}, ...]}`.
- The server checks a valid Firebase token, verified email, approved active membership, matching membership email, university access and admin role before contacting ORS. Denied requests do not consume provider requests.
- Only the API server reads `ORS_API_KEY`. The browser configuration and archived migration configuration no longer contain the exposed credential.
- Fixed HTTPS provider endpoints, an Authorization header instead of a key in a query string, no redirects, validated inputs, and controlled errors prevent arbitrary proxying or provider-response/key leakage.
- Provider reads have one 12-second end-to-end deadline and an enforced 2 MiB streamed-body limit, including responses without `Content-Length`.
- Geocoding retains Vadodara search bias/bounds and validates Point geometry. Directions validate LineString geometry and preserve the complete road path in the correct coordinate order.
- Missing configuration, provider auth/quota/outage/network/timeout errors, malformed results and empty directions fail explicitly. No ORS failure synthesizes a route.
- Existing deliberate manual map-click routes remain unchanged. Their pre-existing dashed stop connectors are not presented as newly obtained ORS road geometry; that separate manual-route behavior is outside W0-04.
- The OpenAPI contract and generated client/Zod artifacts were updated together.

## Remaining owner action and acceptance gate

1. Revoke/delete the exposed key in the [ORS dashboard](https://openrouteservice.org/dev/#/login). Source removal cannot invalidate old builds, cached copies or Git history.
2. Ask the agent to re-run the old-key check; it must return 401/403 (a quota error alone does not prove revocation). That result gets recorded here.

Until the old key is rejected by ORS, **W0-04 is not complete**. With no server secret configured, an otherwise authorized admin receives explicit `503 ORS_NOT_CONFIGURED`; no browser-side fallback exists.
